## Rules checked
- Company comes only from the verified token (`cid` claim), never from the request body. Login is the only place a company code is accepted.
- Every platform data access runs inside `withCompany()`; `grep this.db.` finds only shutdown.
- New rows get `company_id` from the transaction by default, and the policy's WITH CHECK refuses a mismatch (tested).
- Migration backfills existing rows into a `default` company (tested from a Phase 0 database).

## Finding sent back to Coder (fixed)
- **FAIL: code.** `wms_app` had INSERT and DELETE on `platform.companies`. The policy made abuse unlikely, but the API must never create or delete companies. Revoked in the migration, covered by a test.

## Accepted notes
- A failed sign-in with an unknown company code is not audited (there is no company to file it under). It still takes the same time as a real attempt.
- `company_id_by_slug` lets anyone check whether a company code exists. Acceptable: codes are not secret, and passwords still protect accounts.
- Tokens issued before this change have no `cid` and are refused; they expire within 15 minutes anyway.
