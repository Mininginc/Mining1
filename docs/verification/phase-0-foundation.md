## Findings sent back to Coder (round 1, now fixed)
1. **FAIL: code.** An admin could deactivate or demote the last active admin and lock everyone out. Fixed in `users.service.ts`, covered by two new tests.
2. **FAIL: code.** No HTTP hardening headers. Added `helmet`, covered by a test.

## Accepted follow-ups (not blocking Phase 0)
- Admin reset of a user's MFA (lost phone). Needed before MFA becomes mandatory.
- Login rate limiting per IP; lockout alone lets someone lock a known account on purpose.
- Access tokens are kept in `sessionStorage`. Move to refresh tokens in httpOnly cookies when the API and app share a production domain.
- Hosting choice, then wire the nightly backup job and off-site copy.
